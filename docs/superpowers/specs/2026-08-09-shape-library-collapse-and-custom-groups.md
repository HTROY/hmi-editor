# 图元库面板：分类折叠 + 自定义分组与拖拽排序

日期：2026-08-09
范围：HMI 编辑器前端（`src/`）

## Problem Statement

图元库面板目前把所有分类（基本 / 供电 / BAS / 通用 / 自定义）平铺渲染。随着自定义库项增多，面板越来越长，用户难以快速定位到需要的图元；自定义图元也只有「自定义」一个混排区，无法按业务自行组织。用户需要折叠不关心的分类，并能创建自己命名的分组来整理自定义图元。

## Solution

图元库的每个分类（内置分类与自定义分组）都可以独立折叠/展开：点击标题整行切换，右侧箭头指示状态，默认全部展开。

自定义图元支持用户自建命名分组：可新建、重命名、删除分组，保存选中/导入 SVG 时选择目标分组，之后也可通过卡片悬停菜单移动库项；无归属的库项统一放在固定「未分组」区，删除分组不会删除库项。

自定义分组支持拖拽排序（专用把手），顺序作为工程数据随工程保存；内置分类顺序固定，「未分组」固定在最后。

折叠状态分两层持久化：内置分类只存 localStorage；自定义分组折叠状态同时写入工程文件和 localStorage，冲突时工程文件优先，老工程缺省时用 localStorage 兜底。搜索时自动展开所有包含命中项的分类，清空搜索后恢复之前的折叠状态。

## Implementation Decisions

- 分组为独立实体：`LibraryGroup { id, name }`，库项通过 `groupId` 引用分组。稳定 id 保证重命名、排序不破坏归属关系，删除分组时仅清空组内库项的 `groupId`（回到未分组），不删除库项。
- 工程数据结构（共识后的 schema）：

```ts
interface LibraryGroup {
  id: string;
  name: string;
}

// LibraryItem 增加可选字段
interface LibraryItem {
  /* 现有 id/name/shape/createdAt/updatedAt 不变 */
  groupId?: string;
}

// ProjectData 新增可选顶层字段
interface ProjectData {
  /* 现有字段不变 */
  libraryGroups?: LibraryGroup[]; // 数组顺序即显示顺序
  libraryUi?: { collapsed: string[] }; // 折叠的自定义分组 id；含 "@ungrouped" 哨兵表示未分组
}
```

- 折叠状态持久化：内置分类折叠只写 localStorage（单键，例如 `hmi-editor:shape-library:collapsed`，值包含内置分类 key 与自定义分组 id 的并集）；自定义分组折叠双写工程文件（`libraryUi.collapsed`）与 localStorage；两者冲突时工程文件优先，工程文件缺省（老工程/新工程）时用 localStorage 兜底。
- 默认状态：全部展开；新建分组默认展开。
- 折叠交互：点击分类标题整行切换，右侧箭头指示状态；各分类独立开合，不提供「全部展开/全部折叠」按钮，不做手风琴模式。
- 搜索联动：存在搜索词时强制展开包含命中项的分类；清空搜索后恢复之前保存的折叠状态。
- 分组管理入口：工具条「新建分组」按钮（追加到列表末尾、「未分组」之前）；标题行内联重命名；标题行删除按钮（需确认）。移动库项：保存表单里选组 + 卡片悬停「移动到分组」菜单 + 直接把库项卡片拖到分组/「未分组」标题。
- 卡片拖放语义：库项拖拽 `effectAllowed = "copyMove"`，拖到画布仍为放置（copy），拖到分组/「未分组」标题为改变归属（move）；拖回当前所在分组视为无操作，不触发保存。
- 拖拽排序：分组标题行左侧专用拖拽把手，整行其余区域仍用于点击折叠；仅自定义分组可排序，顺序即 `libraryGroups` 数组顺序，只随工程文件持久化（localStorage 不存顺序）。搜索过滤时隐藏无命中分组，为避免目标索引错位，搜索期间禁用拖拽排序。
- 重名策略：新建/重命名分组时阻止重名，输入框标红提示「分组名已存在」。
- 升级迁移：老工程无 `libraryGroups`/`libraryUi` 时补默认值；无效 `groupId` 引用清除；分组名重复时规范化保证唯一；库项 id 去重沿用现有逻辑。
- 分组操作与现有库项操作一致，不进入撤销/重做历史；库项/分组变更继续递增 `libraryRevision` 触发自动保存。

## Testing Decisions

- 只测外部行为，不测实现细节：分组 CRUD 的不变式（名称唯一、删除组后库项回到未分组）、排序语义（目标位置正确、id 稳定）、归属移动、折叠集合归一化（增删、工程文件与 localStorage 优先级）、老工程升级结果。
- 核心缝为纯 TypeScript 分组模块（与库项核心逻辑同一层），UI 只做渲染与拖拽事件转发；升级缝复用现有工程数据升级逻辑。
- 测试模块：核心库分组逻辑、工程升级迁移。
- 先例：`src/core/shapes/library.test.ts`（纯函数 + vitest）、`src/core/project/upgrade.test.ts`（旧工程字段归一化）。
- 通过标准：`vitest run` 全绿、`tsc -b` 通过、`vite build` 通过；手工验证路径：老工程打开归入未分组 → 新建分组 → 保存选中/导入 SVG 选组 → 卡片移动分组 → 折叠/展开与刷新恢复 → 搜索联动 → 拖拽排序 → 删除分组回未分组 → `.hmi.zip` 往返。

## Out of Scope

- 全局个人库 / 后端共享库（ADR-0005 已明确后续独立分支）。
- 库项在分组内部的排序/拖拽。
- 内置分类顺序调整、手风琴模式、「全部展开/全部折叠」按钮。
- 分组的图标、颜色、描述、二级分组。
- 分组操作的撤销/重做。
